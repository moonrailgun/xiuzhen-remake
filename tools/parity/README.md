# 截图对齐清单（`manifest.json`）

《修真》复刻的像素验收基础数据。`manifest.json` 是一个 JSON 数组，每项对应 `reference/images/` 里**一张与界面还原相关**的截图，说明它拍的是哪个页面、拍摄年份、有没有被媒体站缩放过、哪些区域必须掩膜、以及**能不能用来做 ±2px 断言**。

- 所有 `size` 都是本次用 PIL 实测的（`Image.open(...).size`），不是抄报告——报告之间有出入。
- 所有 `scale` 都由该图内**已知固定尺寸的 UI 元素**量出来，`scale_basis` 写明用了哪把尺子、实测值是多少。
- 生成时间：2026-09-21。共收录 **110** 张，跳过 **49** 张（见下）。

---

## 1. 四种 `use` 的含义

| `use` | 含义 | 怎么用 |
|---|---|---|
| `overlay_2px` | **原生 1:1**，截图没有被缩放过。 | 可以和 Playwright 截图直接叠图，对结构边缘（表格线、边框、图标、控件位置）做 **±2px** 断言。 |
| `ratio_4px` | 被媒体站缩放过（`scale` ≠ 1.0）。重采样后每个像素都被搅过，绝对坐标不可信。 | **只比区块比例**：先把截图内坐标除以 `scale` 折算回页面坐标，再断言各区块的相对位置与宽高比，容差 **±4px**。不要做像素级 diff。 |
| `text_only` | 缩得太狠、或是 GIF 抖色、或被后加标注盖住，几何与取色都不可靠。 | **只核文案**（逐字转录、表头名、链接文字、数值），不做任何几何断言。 |
| `excluded` | 两种情况：①**重复图**，同一张截图的另一个（更小的）版本，已有更好的同源图；②内容整体属于**基准期（v1.2.1 / 2008-12）之后**的资料片，且无法局部规避。 | 不进验收流程。`notes` 会写明是哪一种、以及应该改用哪张。 |

> `use` 判的是「能不能做像素断言」，`excluded_regions` 判的是「哪块内容不属于基准期」。
> 一张 `overlay_2px` 的图也可能带 `excluded_regions`（例如 #98 门派页是原生 1:1，但『仙府』标签和功德表都是资料片后的东西）。

### 字段说明

| 字段 | 说明 |
|---|---|
| `id` | 截图编号，对应 `reference/images/_contact-sheets/index.json` 的键 |
| `file` | 相对仓库根的路径 |
| `size` | `[w,h]`，PIL 实测 |
| `md5` | 整文件 MD5，用来做重复图校验 |
| `page` | 对应复刻里的哪个页面 / 浮窗 |
| `evidence_year` | 由文章目录名推出的证据年份 |
| `scale` | 缩放系数，`1.0` = 原生未缩放 |
| `scale_basis` | 判定依据：用了哪个已知固定尺寸元素、实测多少 / 原生多少 |
| `origin_offset` | `[x,y]`：该截图左上角相对整页 `#gpage` 原点的偏移。**换算式：`页面坐标 = origin_offset + 截图内坐标 / scale`**。整项为 `null` = 无锚点；分量为 `null`（如 `[247, null]`）= 只有那一个方向有锚点（多见于弹窗：`#rwindow` 的绝对 `top` 写在已丢失的 `oui.css` 里）。 |
| `masks` | 比对前必须涂掉的矩形，`{rect:[x,y,w,h], why}`，坐标是**截图内坐标** |
| `excluded_regions` | 含基准期之后元素的矩形，同上格式 |
| `notes` | 其它要点 |

## 5. Playwright 验收注意事项

### 5.1 必须做的

1. **`deviceScaleFactor: 1`**。这是硬性前提。默认或 Retina 下的 2 会让截图变成 2 倍尺寸，本清单里所有 `size` / `scale` / `origin_offset` / `rect` 全部作废。
   ```js
   const ctx = await browser.newContext({
     viewport: { width: 1020, height: 900 },
     deviceScaleFactor: 1,
   });
   ```
2. **视口至少 1000px 宽**。页面定宽 `#gpage = 1000px`，留一点给滚动条；截图时用 `element.screenshot()` 截 `#gpage` 而不是整页，避免滚动条宽度污染坐标。
3. **比对前把 `masks` 与 `excluded_regions` 两组矩形都涂掉**（两边同涂：参考图和复刻截图）。Playwright 的 `screenshot({ mask: [...] })` 只能遮 Locator，这里是截图内的裸坐标，得在图像层面涂。
4. **冻结一切会动的东西**：`#servertime` 服务器时间、各倒计时 `<span start="秒数">`、`loading.gif`。截图前把它们替换成固定文本，否则每次 diff 都不一样。
5. **掩膜掉所有浏览器原生控件**。`<select>` / `<input>` / `<radio>` 的外观取决于操作系统主题——参考图是 Windows XP Luna（或 Win7 Aero），本机是 macOS，永远对不上。清单里建号页与炼制页的这些控件都已给出 `rect`。

### 5.2 别期待的

6. **不要期待字形逐像素一致**。原版是 **12/13/14px 宋体位图字（无抗锯齿）**，现代浏览器一定会抗锯齿。断言要建立在**结构边缘**上：表格线、边框、图标位置、区块 bbox；文字区域建议一并掩膜，或改用 SSIM / 边缘图比对而非逐像素。
7. **参考图全是中等质量 JPEG**（8×8 块噪点明显，红绿饱和色边缘发糊，`reference/images/` 里**一张 GIF/PNG 原件都没有**）。逐像素精确比对必然失败，一律用带容差的比对。`#109` / `#110` 还是 GIF 抖色，取色结果不可信。
8. **1px 表格线不是 `border`**。原版是 `table.tablebg` 的背景色从 `cellspacing=1` 的缝里透出来（线色 `#d1d1d1`，`cellpadding=3`）。复刻如果用 `border-collapse` 画线，亚像素舍入会和参考图差 1px——这正是给 ±2px 容差的原因。

### 5.3 坐标怎么换算

9. `页面坐标 = origin_offset + 截图内坐标 / scale`。
   - `scale = 1.0` 且 `origin_offset` 两个分量都有值 → 可以直接把复刻页面截图按 `origin_offset` 裁出同一块，做 ±2px diff。
   - `origin_offset` 为 `null` 或含 `null` 分量 → 只能先用某个共同特征（页标题横幅左上角、表格左边线、墨框左上角）对齐，再比。
   - `origin_offset` 的精度：由页标题横幅或 DOM 相对坐标反推，**±4px**；`notes` 里单独标注了更差的几张。
10. `ratio_4px` 的图请**不要**先把截图放大回 1.0 再做像素 diff——上采样只会把重采样误差放大。正确做法是把**测出来的区块 bbox** 除以 `scale` 折算成页面坐标，再和复刻的 bbox 比，容差 ±4px。

### 5.4 基准期

11. 基准版定在 **v1.2.1 / 2008-12**（见 `docs/research/01-versions-and-systems.md` §2.3）。清单里 23 张 `excluded` 中有一半是「原生但内容属资料片」。**如果基准期上调到 2009-09 之后**，金丹页 #100、商城 #78、仙府 #17 #18 #101 #102、门派功德 #103 会立刻变成可用的 `overlay_2px`——那会让 1:1 图从 53 张涨到 59 张。改基准期时记得重跑这份清单。
